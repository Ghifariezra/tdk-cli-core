# Repo memory

Hard-won, repo-specific facts for anyone (human or agent) working here. Keep entries short, dated, and about things the code cannot tell you. Add one line when a small PR or task teaches you a trap; delete lines that stop being true.

## Verify before you push
- Lint and typecheck from `cli/` by exit code, not by `| tail`: `./node_modules/.bin/biome check . ; echo $?` and `./node_modules/.bin/tsc --noEmit ; echo $?`. `npx biome` runs an unrelated v0.3.3 package that exits 0 without checking.
- Run `npm run build` before vitest when `src/` changed: the e2e tests spawn `cli/bin/tdk.js`, which imports `dist/`.
- 2026-10-07 (#124): `scripts/benchmark/cli-startup.mjs` measures `flisk status` including its read-only Tilt availability probe; when Tilt is absent from `PATH`, each sample can spend about 10 seconds in that probe. Use the benchmark script's `--skip-status` for smoke runs and treat default status timings as probe-dominated.
- On Windows, TypeScript preserves CRLF inside multiline template literals in generated `cli/dist` even with `--newLine lf`; normalize emitted files to LF before staging.
- BSD sed (macOS) has no `\b`; use python `re.sub` or perl for renames and confirm with `grep -c`.
- A red test must be red for the right reason: temporarily remove the fix and read the failure. Common ways a test is red wrongly: a JS template literal evaluating `${...}`, JSON `true`/`null` pasted into Starlark (`True`/`None`), a too-narrow regex.
- Do not leave `.skip` on a failing test; fix the code or the setup.
- 2026-10-20 (#1736): a fish option completion offers its values after the flag only when the line carries `-r` (`complete -c flisk -f -n '...' -l type -r -a 'a b'`); without `-r` fish suggests nothing and without `-f` it also lists files. The stack names for the completions come from `flisk stacks --json`, because the human output prints them without the `  - ` prefix the old script grepped for (so it never matched).
- 2026-10-20: `vite` 8.3.4 pulls `rolldown` 1.2.14 and reproduced 30s test-timeout failures across the vitest full suite (`doctor.test.ts`, `project-env-e2e.test.ts`, `stack-features-e2e.test.ts`); `vite` 8.3.3 keeps `rolldown` 1.2.11 and the full suite matches the `origin/main` baseline. When a Vite advisory has a patched minimum, pin that minimum instead of the latest.
- 2026-10-20: `cli/pnpm-lock.yaml` had drifted from `cli/package.json` (8 mismatched specifiers) and `pnpm install --frozen-lockfile` failed there. Regenerate it with `pnpm install --lockfile-only` in `cli/` and re-check it against `cli/package.json`; `bun.lock` is the lockfile CI actually installs from.
- 2026-10-20 (#1734): commander keeps an option's value *and* its source between in-process `parseAsync` calls, so `getOptionValueSource("type") === "cli"` still reports an earlier run's flag; a test that tells an explicit flag from its default must spawn the CLI. A flag with a default value (`--type backend`) cannot be read from the value alone.
- 2026-10-21 (#1731): The `flisk resource` pickers only run when `process.stdin.isTTY`, so a piped or scripted run never asks. A test reaches them by running the command in process (`runCommandInProcess`) with `vi.mock("../../utils/prompt.js")` and `Object.defineProperty(process.stdin, "isTTY", { value: true })`, and by importing the command per case (`vi.resetModules()`), because commander keeps the option values of the earlier parse.

- 2026-10-08 (#88): In doctor-runtime tests on Windows, runHostCommand uses execFileSync instead of the injected exec callback; mock execFileSync or stub process.platform when a test needs to provide command output.

## PR and CI traps
- 2026-10-22: A test that spawns a real server must take its port from the OS (`server.listen(0)`), not from a guessed range. `resource-agent.test.ts` guessed `4800 + random(500)`, which is inside the agent range the CLI assigns to scaffolded services, so it collided with a parallel worker and the runtime exited before binding — the CI `Test` job failed with "agent did not start" and no diagnostic, because the child's stdio was `ignore`. Take the port from the OS, capture the child's stdout/stderr, and kill it in `finally` so a failed run does not keep holding the port.
- 2026-10-22: A loopback URL in a test turns into a SAST finding as soon as the port folds into a literal. Semgrep folds `let port = 4800` into the request URL and then reports `http://127.0.0.1:4800` as "Unencrypted request over HTTP detected" (`typescript.react.security.react-insecure-request`), which the `Semgrep OSS` check run lists as new alerts on the changed lines and fails. A port that comes from the OS is not foldable on its own, but `let port = 0` is. Build the URL in a helper (`agentUrl(port, path)`) so the fetch argument is not a string literal, and keep the literal out of the port.
- 2026-10-21 (#1816): the `📋 Summary` job waited for `e2e-examples` and `e2e-platforms` on every CI run, but those workflows only trigger on a pull request, a merge queue entry or their own manual dispatch. A push to main therefore burned the whole 30-minute deadline waiting for a check that can never report, and then failed. The gate list now depends on the CI event (`scripts/e2e-gate-expectations.mjs`, checked by `scripts/e2e-gate-expectations.test.mjs`), and a gate whose workflow never started for the commit fails early instead of at the deadline. A gate can only be waited for when its workflow triggers for that event.
- 2026-10-21: A reference to a package that is still published keeps its old name. `@tdk-landscape/tdk-cli-core` is what `flisk upgrade` and the global install have to remove, so it stays named in `LEGACY_PACKAGE`; pointing it at the current package would uninstall the CLI instead of the leftover install. The OpenSSF Scorecard score moved to `flisk-sh/flisk` on 2026-10-23 (a manual `scorecard.yml` run published it; the API had 404'd for the new path until then), so `oss-score-gate.yml` reads only the current repo path and has no old-path fallback. If the viewer shows "not found" again after a rename, re-run `scorecard.yml` on main.
- 2026-10-20: `repository_vulnerability_alert` is not a workflow trigger — GitHub's event list has no such entry and actionlint rejects it. To react to a new finding, use `workflow_run` on the workflow that produces it; that trigger needs a `# zizmor: ignore[dangerous-triggers]` comment when the job checks out the default branch instead of the triggering run.
- 2026-10-12 (#1046): Native Windows cannot execute the root POSIX `prepare` hook during `bun install`; use the frozen install with `--ignore-scripts`, then run build, typecheck, lint, and tests explicitly.
- 2026-10-08 (#443): In the Windows sparse checkout, project-templates.test.ts fails because its examples/ fixture is omitted, while tilt.test.ts expects POSIX / paths. Report those failures as checkout/platform-specific rather than as a Linux full-checkout baseline.
- `cli/dist/` is gitignored but tracked file by file: after `npm run build`, `git add -f` new dist files. A missing one fails `README quickstart on a clean machine` with `ERR_MODULE_NOT_FOUND`.
- Never commit a `cli/node_modules` symlink (`.gitignore` does not match a symlink). It stalls `bun install` and makes Lint/Test/Typecheck look cancelled.
- Open every PR against `main`; no stacked PRs (a stacked PR merged into a squash-merged base never reaches `main`). After a merge, check the files exist on `origin/main`.
- A PR can be squash-merged before your last commit lands: check `gh pr view N --json state` before pushing a follow-up, and open a new PR from `main` if it merged.
- Test job limit was 1 minute until #407; a job "cancelled" at exactly the limit is a timeout, read the step log before rerunning. `wsl2-smoke` is manual-only since 2026-10-07 (workflow_dispatch; its job is skipped on PRs and pushes, which still satisfies the required check). It was flaky on `setup-wsl`'s hard-coded `wsl --update` 403 on windows-2022 and on apt/Docker mirrors (#716, #717).
- Pinned hashes in `resource-backend-languages.test.ts` change when scaffold output changes; re-capture them on purpose and say why in the test comment.
- 2026-10-17 (example-e2e run 39058693205): the image build installs without a lockfile (L2 copies only package.json), so `orders-app` resolved `rollup@4.64.9` in the window after publication: the gnu platform package was live at 18:33:49Z, `rollup-linux-x64-musl` only at 18:35:35Z, and Alpine's musl loader then failed with `Cannot find module @rollup/rollup-linux-x64-musl`. `orders-app` pins `rollup` in `overrides`; bump the pin only after `npm view @rollup/rollup-linux-x64-musl time` shows the version.

- 2026-10-08 (#873): A build tool used by a `prepack`/`build` script must be a declared devDependency of the package that runs it (`cli/`). A stray copy in `node_modules` from an earlier `bun add` hides the omission locally; CI's clean `bun install --frozen-lockfile` fails with `ERR_MODULE_NOT_FOUND`. Verify with `rm -rf node_modules cli/node_modules` and a frozen install before pushing.

- 2026-10-18 (#1396): `flisk runtime --check-assets --json` reports `ok: false` in a source checkout (its assets exist only in the packaged install), and `flisk doctor --json` exits by host state, so its flag-contract row checks the envelope only, not the exit status.

- 2026-10-17 (#1396): `flisk upgrade --yes` updates the git-installed CLI checkout and rebuilds it; never run it from a test or a probe. Its flag-contract row stays exempt for that reason.

- 2026-10-17 (#1384): `flisk project` and `flisk up` stop at the machine checks (Docker, Compose, Tilt, Bun) in a bare `node:22` container and exit 1 before scaffolding, so a lifecycle smoke can only exercise `flisk --help` there. `scripts/package-lifecycle-smoke.sh` is the reference for running a packed tarball in a clean container.

- 2026-10-18 (#1385): Vitest's `--reporter=json --outputFile.json=<file>` drops the console summary unless `--reporter=default` is also passed; `test:coverage` passes both. The PR summary reads `cli/test-results/vitest.json`, so keep that flag pair and the `test-results/` ignore entry together.
- 2026-10-18 (#1302): a `run:` scalar that contains `: ` (for example `echo "erp: weekly"`) fails to parse as YAML; use a `run: |` block. `node scripts/check-ci-inventory.mjs` reads every job, so a new gate needs an inventory entry too.
- 2026-10-17 (#1387): every new workflow job needs its own entry in `.github/ci-inventory.json` (tier, reason, owner) or `node scripts/check-ci-inventory.mjs` fails; run `bun install --frozen-lockfile` first, since the checker imports `yaml`. The publish gate in `release-binaries.yml` reads release-candidate runs by `head_sha`, so a candidate must run on the exact commit that will publish.
- 2026-10-18 (#1382/#1383): an E2E job with `sparse-checkout` must include `scripts/e2e` as well as `.github/actions`: the evidence composite and `retry-infra.sh` run from the workspace, and a missing script only shows up when a job fails. Wrap only infrastructure in `scripts/e2e/retry-infra.sh`; a wrapped assertion would hide a real failure.
- 2026-10-20: `actions/github-script` runs with `retries: 0`, so one transient GitHub 5xx fails the whole job: the hall-of-fame search query got a `POST /graphql - 502` and the run died with GitHub's unicorn HTML page instead of a JSON error. Wrap API calls in an in-script retry on 429/5xx, and re-check before re-creating an issue so a retry cannot duplicate it.
- 2026-10-21 (#1742): Node.js reads `--env-file` as one of its own options wherever it appears in the command line, so on the npm install (a node script) `flisk up --env-file missing.env` dies in node (`node: missing.env: not found`, exit 9) before the CLI runs. Node stops reading its own options at `--`, but the npm shim puts the user arguments behind the script path, so the CLI cannot intercept it. A CLI option with that name therefore has to resolve its path the way node does (relative to the current directory), and the prebuilt binary (the official installer) is the only install where the CLI's own message appears.
- 2026-10-23 (v1.3.207): the `release branch protections` ruleset enforced required status checks at branch creation, so the release workflow's push of a fresh `release/bump-*` branch was declined with GH013 ("2 of 2 required status checks are expected") — after npm and the binaries were already published, which skipped the signing steps that ran below it. Fixed twice: `do_not_enforce_on_create` is on for that ruleset, and `Commit the version bump` is now the last step of the publish job. Release repair recipes: `docs/releasing.md`.
- 2026-10-23: `publish-unscoped-npm` fails with `404 PUT .../flisk` because the unscoped `flisk` package does not exist on npmjs.com and OIDC cannot create it; the owner must create it once and add a trusted publisher (or set `NPM_TOKEN`). A `📦 Pack CLI` `cli/dist is stale` failure on a main push is fixed by `npm --prefix cli run check:dist` + `git add -f cli/dist` + a `Rebuild cli/dist` commit — JSDoc-only `cli/src` edits still change the emitted `.d.ts`.

## Engine and generators
- 2026-10-17 (agent E2E): a new named volume is seeded with the image directory's owner, so a path the non-root `bun` user writes to must be created with `chown bun:bun` in the image (EACCES on the first write otherwise). `docker kill` does not auto-restart under `restart: unless-stopped` (manual-stop semantics); `kill -9 1` from `docker exec` is a no-op (PID 1 ignores its own namespace's SIGKILL). Test crash recovery with `docker kill` then `docker start`, and say that auto-restart was not observed.
- 2026-10-17 (agent resource type): a new `appType` must be added to every exact list or it fails late: `CREATABLE_RESOURCE_TYPES` and its `toHaveLength` in `resource.test.ts`, the exact `VALID_RESOURCE_TYPES` list in `validation.test.ts`, `KNOWN_SERVICE_FIELDS` in `service-manifest.ts` (a new service.json key otherwise prints "unknown field is preserved" on `flisk up`), and `RESOURCE_CONFIG_FIELDS` in `service-schema-contract.test.ts`.
- 2026-10-10 (#1023): Starlark has no implicit string-literal concatenation (write one triple-quoted literal or join with `+`), and a shell regex inside a Starlark string needs each backslash doubled (`\\(`); a single `\(` fails to load with "invalid escape sequence".
- 2026-10-10 (#1023): A resource that the engine registers but the Tiltfile focus filter does not name is silently disabled ("currently disabled" from `tilt trigger`). Any new per-service resource must be named in `cli/templates/Tiltfile.hbs`'s focus block, and the engine must export any helper the template calls through `engine/Tiltfile` and the root `Tiltfile`.
- 2026-10-10 (#1023): `docker buildx bake --allow fs.read=<dir>` needs Buildx 0.19 or later; gate the flag on the version, not on the presence of `--allow`.
- From a projectless MCP client, the server's launch directory may not be the intended Flisk project; pass an absolute `projectPath` to each tool call (2026-10-09).
- A changed `.star` file reaches a running container only after re-vendoring (`flisk project --yes`), a Tiltfile content change, and an image rebuild. Byte-identical output logs `Skipping ... (no changes)`.
- Check a BYO example through `flisk up` (`tests/e2e/resource-types/bring-your-own/verify-byo-tdk.sh`), not only a standalone `docker run`: Flisk adds a `Host: api.<project>.localhost` header, a Postgres `DATABASE_URL`, and its own bind expectations.
- Do not make a service run its own migrations to prove a database path works (2026-10-04, #533): a fixture whose `index.ts` ran `bunx prisma migrate deploy` crashed in CI with `Cannot find module '@prisma/engines'`, then looped until the script timed out. Use a `migrator` resource and check Postgres, migrator, API order through `flisk up`.
- 2026-10-11: A `local_resource` with `serve_cmd` and `auto_init=False` never starts on `tilt up`, so its loop does nothing until someone triggers it. Engine scripts reach a generated project only under `.tdk/.tdk-out/tdk-cli-ext/engine/...` (init vendors all of `engine/`); `.tdk-out/ext/...` does not exist.
- Say only what a run observed; mark everything else "not run" in docs and PRs.
- Resource scaffolds must write current keys (`dependsOn`, `healthCheckPath`); `flisk doctor` warns on deprecated and unknown ones.
- `flisk config verify` validates discovered `service.json` files and generated service snapshots as well as project files; `flisk config regenerate` rewrites project outputs, while service outputs are written on `flisk up` (2026-10-05).
- A feature-off Postgres `dependsOn` needs `services/platform/database-management/docker-compose.yml` in both CLI and Tilt generated-file allowlists; test from a missing Compose, since a pre-existing file hides a denied write. Tilt registers all siblings before applying `--focus`, so force-start checks must use the focus resource list, not `should_enable` (2026-10-06, #646).
- Doctor's default-focus Postgres warning must inspect the generated Tiltfile, spec, and vendored `CORE_INFRA` mapping; `project.json` alone cannot prove the feature path, and a project-scope `dependsOn` result must not hide that warning (2026-10-06, #646).
- Env and secrets: no JWT in generated files; Compose takes `JWT_SECRET` from the project `.env`; `completeEnvFile` appends missing keys and never rotates.

- 2026-10-10 (#1025): the Go live-reload e2e job can fail on a loaded runner (edit-timing assertions) and pass on rerun; check the rerun before assuming a regression. Local runs under load average > 20 are not usable for its timing assertions.

## Housekeeping
- 2026-10-08: Compose project (`<stack>-autogenerated`), container (`<stack>-autogenerated-<svc>-1`) and image (`<stack>_<svc>:dev`) names are not project-scoped. A scratch project with the same stack name as a running one (even on another `TILT_PORT`) replaces its containers and `--remove-orphans` deletes its others. Give verification projects a unique stack name, and never `flisk down` a colliding run.
- 2026-10-07 (#670): The archived public `flisk` root (`1714637`) is separate from the filtered `tdk-cli` history imported into `main`. Keep README chronology clear about both histories and the later repository and npm dates.
- Verification scripts must remove every tag of `app_<project>` images (Tilt adds a `tilt-<hash>` tag) and the project's containers and networks.
- `PAGES_SYNC_TOKEN` is not set, so the schema publish workflow succeeds but does nothing.
- 2026-10-21 (#1793): GitHub Packages only accepts scoped npm names — publishing an unscoped package to `npm.pkg.github.com` answers `404 Not Found` on the PUT, so the CLI package has to stay `@flisk-sh/flisk`. `actions/setup-node`'s `scope:` input is what routes the scope: it writes `<scope>:registry=https://npm.pkg.github.com` into the generated `.npmrc` and defaults to the repository owner, so a stale scope leaves the package resolving to the public registry while the "verify the GitHub Packages install" step still passes.
- 2026-10-14: A git-linked Flisk install can point at a local feature branch whose remote ref was deleted; upgrades must target `origin/HEAD` and preserve the checkout when it has uncommitted changes.
- npm publication can succeed before cached registry metadata shows the new version (2026-10-05, importer 0.1.1): wait for ordinary `npm view` and fresh-cache `npx` to see it before removing release gates; verify the registry tarball against the workflow artifact.
- 2026-10-09 (#966): workflows with `working-directory: cli` must invoke repository-root helpers as `node ../scripts/...`; workflows checking out only an external fixture cannot use those helpers from the workspace root.
- 2026-10-09 (#966): install workflow-only npm tools with `npm ci` from a committed lockfile into a scoped prefix, not globally; runner toolcache paths can make Git dependency installs fail with `ENOTDIR` during rename.
- 2026-10-09 (#972): committed `cli/dist/*.map` files are one-line generated JSON and repeated PR conflict hotspots; TypeScript source and declaration maps are disabled so builds stop reintroducing them.
- 2026-10-14: The warm-start benchmark must ignore `*-typecheck` Tilt resources when deciding startup is settled; they are non-blocking and may remain busy after all target containers are healthy.
- 2026-10-16 (#1235): Traefik disables ALL plugins when one fails its integrity check ("Plugins are disabled because an error has occurred"), so every plugin middleware then shows as "invalid middleware type or middleware does not exist". `sablier-traefik-plugin` v1.3.1 failed on `traefik:v3.7.14`; v1.3.0 loads. Before bumping the plugin or Traefik pin, run `tests/tilt-engine/test_sablier_plugin_loads.py` (Docker and network only, no license). The licensed cold-start E2E only runs on main, so a bad pin otherwise stays red there.
- 2026-10-16 (#1235): `resource["_manifest"]` is the ORIGINAL service.json, not the normalized one, so defaults the parser fills in (`syncs`, `appType` derived from the path) are missing there. `cli/templates/Tiltfile.hbs` mirrors engine registration logic to build the focus-mode enable list; read such fields from the resource entry (as `_register_single_resource` does) or a registered resource is silently disabled (`update=none`). That is what kept a scaffolded deferStart service's `<name>-image` from ever building.
- 2026-10-18 (#1386): `flisk up` does not refuse an unknown `dependsOn` name (`--only` silently drops it); only `flisk doctor --json` reports it ("Shared platform Postgres" check). A broken service.json fails `flisk up` at discovery, before `.tdk/.tdk-out` is written. Lint with `cd cli && ./node_modules/.bin/biome check .` (biome 2.x); `npx biome` at the root is the unrelated 0.3.3 package.
- 2026-10-18 (#1467): `agent sessions` can run in-process with `agentCommand.parseAsync(["sessions", ...], {from: "user"})` after `process.chdir`, but (a) `findProjectRoot`/discovery is cached for 1 s and not keyed by project, so call `clearDiscoveryCache()` before each run; (b) the top-level handler catches the thrown `process.exit` and prints a second `INTERNAL` envelope, so read the first JSON line only; (c) Commander keeps option values between `parseAsync` calls, so never pass a flag in one in-process case that a later case expects absent. `cli/test-results/` and `cli/coverage/` from an earlier coverage run make `biome check .` exit 1 (biome 2 does not skip them), so delete them before biome.
- 2026-10-18 (#1467): `runCommandInProcess` (cli/src/test-support) reads the exit code from a `process.exit` spy's `mock.calls`; read it before `mockRestore()`, which clears those calls, or every case reports `status` undefined.
- 2026-10-20 (#1735): on macOS a temp dir under `/var/folders` becomes `/private/var/folders` once `process.chdir` resolves it, so `expect(fn).toHaveBeenCalledWith(tempDir)` fails; build the path with `realpathSync`. Three CLI tests fail on macOS for unrelated reasons (`paths.test.ts`, the force-yes path assertion, and the saas-starter network clone) — check them on a clean tree before blaming a change.
- 2026-10-21 (#1620): `showErrorAndExit` has defaulted to exit code 1 since it was introduced (fc836c19), so `flisk up` on native Windows has always exited 1; the "exits 2" claims in README.md and docs/comparison.md were docs-only mistakes. The `CONTRIBUTING.md` exit-code table is now pinned to the implementation by `cli/src/commands/__tests__/up.test.ts`.
