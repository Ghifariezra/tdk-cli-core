# Luna ticket acceptance contracts

This spec records the user-visible contracts for the CLI experience tickets in the Luna batch. Ticket 5 (`shop-real`) is intentionally deferred.

## Requirement: Bring-your-own resources validate and run without generated application code

The CLI and service schema MUST accept bring-your-own resources with project-defined stack names. `stack` MUST be a free-form string. `exposeViaProxy` MUST be a schema-declared boolean and MUST be honored only for bring-your-own resources.

### Scenario: Create a Dockerfile-backed resource

- **WHEN** a user runs `flisk resource <name> --type byo --stack shop --yes`
- **THEN** the CLI creates `services/shop/<name>/service.json`
- **AND** writes `appType: "bring-your-own"`, `stack: "shop"`, and an assigned port in the 4000–5999 range
- **AND** creates a Dockerfile and health configuration using that assigned port only when the selected Dockerfile does not already exist
- **AND** does not generate `src/`, `package.json`, or tests

### Scenario: Use an existing image

- **WHEN** `--image <image>` is supplied
- **THEN** the manifest records that exact image and omits `dockerfile`
- **AND** the command does not create a Dockerfile

### Scenario: Disable proxy routing

- **WHEN** `--no-proxy` is supplied
- **THEN** Commander sets `options.proxy` to `false`
- **AND** the manifest contains the schema-declared `exposeViaProxy: false`
- **AND** `featuresEnabled` is preserved

### Scenario: List and preview the resource

- **WHEN** the resource has been created
- **THEN** `flisk resources` lists it
- **AND** `flisk up --dry-run <stack>` includes it without starting services

### Scenario: Verify a non-generated Python resource in CI

- **WHEN** the BYO contract E2E copies a pre-written Python Dockerfile fixture into a Flisk project and runs `flisk resource <name> --type byo --stack shop --dockerfile ./Dockerfile --port 4500 --yes`
- **THEN** the fixture files remain byte-for-byte unchanged
- **AND** the resource has a schema-valid `service.json` with `appType: "bring-your-own"`, `stack: "shop"`, and `port: 4500`
- **AND** Flisk does not create `src/`, `package.json`, or `tsconfig.json`
- **AND** `flisk up shop --dry-run` lists the resource without requiring Docker or Tilt
- **AND** the contract E2E does not add Python, Java, or other language generators

### Scenario: Boot the checked-in Python BYO fixture

- **WHEN** the nightly or manually dispatched boot E2E copies the Python fixture into `services/shop/legacy/`, registers it with `flisk resource legacy --type byo --stack shop --dockerfile ./Dockerfile --port 4500 --yes`, and runs `flisk up shop`
- **THEN** the service health URL returns HTTP 200 with body `ok` within three minutes
- **AND** `flisk down` cleans up the stack
- **AND** the test confirms `service.json` has `appType: "bring-your-own"` and `port: 4500`, no `src/` or `package.json` was created, and the copied Dockerfile matches the fixture

## Requirement: Doctor uses exact remediation copy

Doctor MUST preserve these exact fix strings:

- Port 80: `Stop the process bound to port 80, or stop local nginx/caddy. Then: flisk doctor`
- Port 5432: `Stop local Postgres or change the host port. Then: flisk doctor`

Doctor MUST preserve the exact completion and WSL2 guidance strings in its CLI tests.

## Requirement: Eject documents retained files and exact recovery

`flisk eject` MUST fail outside a project with `flisk eject: no .tdk/project.json in this directory or parents`. Its dry-run MUST list generated project outputs only and MUST NOT write `EJECTED.md`.

On confirmation, it MUST create an `EJECTED.md` with this exact body:

````text
# Ejected from Flisk

These files were generated by Flisk. You can keep using Docker and Tilt without the Flisk CLI.

Keep:
- Tiltfile
- Dockerfiles
- compose files Flisk wrote
- Traefik / proxy config Flisk wrote

Optional to delete later:
- .tdk/
- service.json files (only if you no longer want flisk up)

To go back: install Flisk and run `flisk config regenerate`.
````

It MUST retain the existing success output contract.

## Requirement: WSL2 guide and README state platform support accurately

The guide MUST contain this exact page:

````text
# WSL2

Flisk supports Ubuntu on WSL2. Native Windows is not supported.

## Install
1. Install Docker Desktop and enable WSL2 integration for your distro.
2. In Ubuntu: install Tilt.
3. In Ubuntu:

curl -fsSL https://flisk.sh/install.sh | sh
flisk doctor
flisk project example
cd tdk-example
flisk up

Open the URL printed by flisk networks from Windows browser. *.localhost should work on recent Windows.

Common failures
Docker not visible in WSL: enable the distro in Docker Desktop → Resources → WSL integration.
Port 80 taken by Windows IIS: stop IIS or skip host bind docs if Flisk uses Traefik on 80.
````

README MUST use `Windows native is unsupported. WSL2 Ubuntu is supported. See docs/wsl2.md.`

## Requirement: Honest tool comparison uses the agreed headings

The comparison page MUST use these headings and exact body text:

- `# Flisk vs Compose vs raw Tilt`
- `## Use Flisk when`
- `## Do not use Flisk when`
- `## vs docker compose`
- `## vs raw Tilt`
- `## Known limits`

Under `## Use Flisk when`, it MUST list `New TypeScript/Bun services`, `You want one service.json per service`, and `You do not want Kubernetes locally`. Under `## Do not use Flisk when`, it MUST list `You already have a Compose or Tilt setup you like`, `The apps are not containers`, `You need native Windows`, and `You need Flisk to generate Go/Java/Python apps (use bring-your-own)`. The `vs docker compose` section MUST say `Flisk generates compose-like Docker + Tilt live update. Compose is simpler for 2–3 services you already wrote.` The `vs raw Tilt` section MUST say `Flisk writes the Tiltfile for you. If you already maintain a Tiltfile, stay on Tilt.` Known limits MUST list `Community is small`, `Generators are TypeScript-first`, and `100-service benchmark uses tiny /health stubs, not real apps`.

## Requirement: First-boot issue template uses the agreed fields

The issue template MUST use `title: "boot: "`, `labels: ["show-and-tell"]`, and exactly these field IDs: `os`, `version`, `minutes`, `broke`, and `cmd`. Their labels MUST be `OS`, `flisk --version`, `Minutes until first healthy URL`, `What broke`, and `Commands you ran`, respectively. The `minutes` field MUST be optional.

## Requirement: Quickstart continues to run doctor

The Quickstart E2E MUST run `flisk doctor` after initializing a project with `flisk project --yes`, so doctor output remains covered without treating the expected pre-project state as a doctor regression.

## Requirement: Up success message remains covered

The CLI MUST test that the successful `flisk up` output includes `Tilt UI:` and `flisk networks`, plus the selected Tilt port without a trailing slash.
